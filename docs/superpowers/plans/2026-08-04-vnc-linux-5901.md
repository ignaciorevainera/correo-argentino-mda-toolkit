# VNC Linux (UltraVNC :5901) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the existing `vnc` button/shortcut connect to Ubuntu/Debian terminals via UltraVNC on port `5901` with the shared password `d9abf665`, so operators stop getting a password/port prompt and connect in one click.

**Architecture:** The frontend already has a `vnc` button (key `8`) that calls `invoke("run_vnc", { hostname })`. The Rust backend `run_vnc` currently launches `vncviewer.exe <host>` with no port and no password, so UltraVNC prompts the operator. We extract the command-line construction into a pure, unit-tested helper `build_vnc_args(hostname)` that emits `<host>::5901 -password d9abf665`, then wire `run_vnc` to use it. No new Tauri permissions, no new windows, no new frontend buttons required.

**Tech Stack:** Tauri v2 (Rust backend, `std::process::Command` + `CREATE_NO_WINDOW`), React 19 / TypeScript frontend (`@tauri-apps/api/core` `invoke`). Rust unit tests via `cargo test` (the repo already ships `#[cfg(test)]` regression tests in `src-tauri/src/lib.rs`).

## Global Constraints

- **Option A (decided):** `run_vnc` spawns `vncviewer.exe` UNQUALIFIED (no path) — Windows resolves it via system PATH. UltraVNC Viewer must therefore be installed on every OPERATOR PC (Windows inside the Correo network), with its dir on PATH (`C:\Program Files\uvnc bvba\UltraVNC\`). Verify per machine with `where vncviewer`. Do NOT hardcode an install path in code. The Ubuntu/Debian target only runs a VNC *server* (listen on :5901); the viewer runs locally.
- Backend commands run on Windows only; `std::os::windows::process::CommandExt` + `creation_flags(CREATE_NO_WINDOW)` (`0x08000000`) is mandatory so no console window ever appears (mirror `run_msra_offer` at `src-tauri/src/lib.rs:160`).
- VNC port is fixed at `5901` and password is fixed at `d9abf665` per operator workflow (8-char VNC max length — exactly 8 chars, valid).
- Frontend convention: hostname resolution (append `.correo.local` for bare names, keep IPs) already done in `launchVnc` (`src/App.tsx:245`); `run_vnc` receives a fully-qualified host and must NOT re-resolve it.
- UltraVNC viewer CLI verified against source: `host::port` (double colon = direct port, not display) per `ParseDisplay` in `vncviewer.cpp`; password flag is `-password <plaintext>` per `ClientConnection.cpp:731-732,1766`.
- `vncviewer.exe` must be on the system PATH on the operator machine (it is preinstalled on Correo Argentino terminals). If missing, `run_vnc` returns an error and the frontend shows it via `showStatus` — no extra handling needed.
- **Security note (normal English):** the password `d9abf665` is hardcoded in source as a `const`. This is a single shared password for all Linux terminals, not a per-user secret, and the user explicitly requires it for one-click connect. Acceptable for this internal desktop tool, but the constant must stay centralized (one place) so it is easy to rotate.

#[tauri::command]
fn run_vnc(hostname: String) -> Result<(), String> {
    StdCommand::new("vncviewer.exe")
        .creation_flags(CREATE_NO_WINDOW)
        .args(build_vnc_args(&hostname))
        .spawn()
